# 홈페이지 문장 작성 가이드

Claude Code 클라우드 세션이 `data/site.json`의 글을 쓰거나 고칠 때 따르는 규칙입니다.

## 수정 범위

- `data/site.json`의 텍스트 필드(`title`, `subtitle`, `about`, `contact`, `items[].summary`, `items[].tag` 등)만 고칩니다.
- `index.html`은 직접 고치지 않습니다. 생성기가 다시 만듭니다.
- 요청에 없는 항목은 바꾸지 않습니다.

## 사실 정보

- 날짜, 링크, 이메일, 연락처, 수치, 수상 이력 같은 사실은 **요청 문장이나 기존 데이터에 있는 것만** 씁니다.
- 요청에 없는 사실을 지어내지 않습니다. 부족한 정보가 있으면 빈 값으로 두고 보고합니다.
- 링크는 `https://` 로 시작하는 것만 사용합니다.

## 길이와 형식

| 필드 | 권장 길이 |
| --- | --- |
| `title` | 60자 이내 |
| `subtitle` | 60자 이내 |
| `items[].title` | 40자 이내 |
| `items[].summary` | 1–3문장, 150자 이내 |
| `about` | 500자 이내, 줄바꿈 가능 |
| `contact` | 한두 줄 |

## 문체

- 기본 언어는 한국어이고, 존댓말(`-습니다`, `-요`)로 씁니다.
- 과장된 표현("최고의", "혁신적인")은 피하고, 구체적으로 씁니다.
- 한 문장에 하나의 내용만 담습니다.

## 요청 해석표

요청에 나오는 말을 아래 필드에 대응시킵니다. 대응이 하나로 정해지지 않으면 "모호한 요청"으로 처리합니다.

| 요청 표현 | 바꿀 필드 |
| --- | --- |
| 제목, 홈페이지 이름, 사이트 이름 | `title` |
| 한 줄 소개, 부제목, 소개 문구 | `subtitle` |
| 소개 글, 나에 대한 글, 단체 소개 | `about` |
| 연락처, 이메일, 전화번호 | `contact` |
| 소식, 게시글, 프로젝트, 항목 | `items[]` (항목 단위 작업) |
| 소식 설명, 요약, 내용 | 해당 항목의 `items[].summary` |
| 날짜 | 해당 항목의 `items[].date` |
| 링크, 주소, URL | 해당 항목의 `items[].url` |
| 태그, 분류, 구분 | 해당 항목의 `items[].tag` (현재 생성기에서는 쓰지 않음) |

## 항목 단위 작업 규칙

`items` 배열은 번호가 아니라 **제목**으로 찾습니다.

- **추가**: 요청한 제목, 날짜, 요약, 링크를 그대로 넣습니다. 날짜가 없으면 `date` 를 넣지 않습니다.
- **수정**: 제목이 정확히 한 개 일치하는 항목만 고칩니다. 두 개 이상 일치하면 고치지 말고 어떤 항목인지 물어봅니다.
- **삭제**: 제목이 정확히 한 개 일치하는 항목만 지웁니다. 일치하지 않으면 아무것도 지우지 않고 보고합니다.
- **순서**: `items` 의 정렬은 생성기가 날짜순으로 처리합니다. 날짜를 바꾸지 않고 순서만 바꿔 달라고 하면 순서가 적용되지 않는다고 알려 줍니다.

## 모호한 요청 처리

아래 경우에는 파일을 고치지 않고 질문으로 되돌려 보냅니다.

- 대상이 두 개 이상이다 (예: "그 소식 지워 줘", 제목이 비슷한 항목이 여럿)
- 바꿀 값이 없다 (예: "날짜를 바꿔 줘"인데 새 날짜가 없음)
- 요청이 사실 정보를 요구하는데 근거가 없다 (예: "수상 내역을 추가해 줘"인데 수상 정보가 없음)

질문은 한 번에 모아서 짧게 합니다.

## 작업 절차

1. 요청을 읽고, 요청 해석표로 바꿀 필드를 정합니다.
2. 모호한 요청이면 고치지 않고 질문합니다.
3. 해당 필드만 고칩니다.
4. `python -m unittest discover -s tests` 로 테스트를 통과하는지 확인합니다.
5. `python update_homepage.py` 로 `index.html`을 생성합니다.
6. 아래 점검표를 확인한 뒤 push합니다.

## push 전 점검표

- [ ] 바꾼 필드가 요청 범위 안에 있다.
- [ ] 제목이 비어 있지 않다.
- [ ] 링크는 모두 `https://` 로 시작한다.
- [ ] 날짜는 모두 `YYYY-MM-DD` 형식이다.
- [ ] 요청에 없는 사실 정보를 추가하지 않았다.
- [ ] 테스트와 생성이 모두 성공했다.

## 보고 형식

보고는 아래 순서로 짧게 씁니다.

1. **바꾼 내용**: 필드마다 `이전 → 이후` 로 적습니다.
2. **확인이 필요한 사실**: 요청에 없어서 비워 두거나 추측하지 않은 항목
3. **보류한 요청**: 모호해서 고치지 않은 항목과 그 이유
4. **검증 결과**: 테스트와 생성 결과, push 한 커밋 주소
