# 홈페이지 자동 업데이트

홈페이지 내용을 **말로 요청하면** 자동으로 고쳐지는 저장소입니다.
코드를 몰라도 아래 순서대로 따라 하면 됩니다.

## 처음 시작하기 (컴퓨터를 잘 몰라도 할 수 있어요)

### 준비물

- GitHub 계정 (이 저장소를 볼 수 있는 계정)
- Claude 계정 (Claude Code 클라우드 세션을 쓸 수 있는 계정)

### 1단계: 요청할 화면 열기

1. 웹 브라우저에서 `claude.ai/code` 주소로 들어갑니다.
2. 로그인합니다.
3. 새 세션을 만들고, 저장소로 `sunnykim717/claude-project` 를 선택합니다.
4. 화면 아래 입력창에 요청을 적고 보냅니다.

### 2단계: 요청을 말로 적기

입력창에는 **하고 싶은 일을 그냥 한국어로** 적으면 됩니다. 아래 예시를 복사해서 빈칸만 바꿔 쓰세요.

| 하고 싶은 일 | 이렇게 적으세요 |
| --- | --- |
| 제목 바꾸기 | "홈페이지 제목을 '○○○의 작업실'로 바꿔 줘" |
| 소식 추가하기 | "소식에 '○○ 행사 안내' 를 추가해 줘. 날짜는 2026-11-03, 요약은 '○○에서 행사를 엽니다.' 야." |
| 소식 지우기 | "'○○ 행사 안내' 소식을 지워 줘" |
| 소개 글 쓰기 | "소개 글을 존댓말로 세 문장 정도 써 줘. 우리 단체는 ○○을 돕는 곳이야." |
| 글 다듬기 | "프로젝트 설명을 더 짧고 쉽게 다듬어 줘" |
| 연락처 바꾸기 | "연락처를 ○○@example.com 으로 바꿔 줘" |

**요청할 때 꼭 지켜 주세요**

- 날짜는 `2026-11-03` 처럼 **년-월-일** 순서로 적습니다.
- 링크는 `https://` 로 시작하는 주소만 쓸 수 있습니다.
- 사실인 정보(날짜, 링크, 연락처, 이름)는 **직접 적어 주세요.** 적지 않은 정보는 세션이 지어내지 않고, 빈칸으로 두고 알려 줍니다.

### 3단계: 세션이 하는 일

세션은 다음 순서로 작업합니다. 직접 할 일은 없습니다.

1. 홈페이지 데이터 파일(`data/site.json`)만 고칩니다.
2. 자동 검사를 돌려 틀린 곳이 없는지 확인합니다.
3. 저장소에 반영(push)합니다.
4. 세션 화면에 **무엇을 바꿨는지** 요약해 보여 줍니다.

요약을 읽고 원하던 대로 되었는지 확인하세요.

### 4단계: 바뀐 내용 확인하기

1. GitHub 에서 이 저장소를 엽니다.
2. 상단 메뉴의 **Actions** 를 누릅니다.
3. 가장 위의 **Update homepage** 항목을 확인합니다.
   - 초록색 ✓ 이면 성공입니다. 홈페이지가 새로 만들어졌습니다.
   - 빨간색 ✕ 이면 실패입니다. 아래 "문제가 생겼을 때"를 보세요.
4. 홈페이지 주소(GitHub Pages 를 켠 경우)에서 바뀐 내용을 확인합니다.

## 문제가 생겼을 때

| 증상 | 해결 방법 |
| --- | --- |
| Actions 에 빨간 ✕ 이 떴어요 | 같은 세션에 "Actions 가 실패했어. 원인을 알려 주고 고쳐 줘"라고 적으세요. |
| 날짜 오류가 나왔어요 | "날짜를 2026-11-03 형식으로 고쳐서 다시 해 줘"라고 요청하세요. |
| 링크 오류가 나왔어요 | 링크 앞에 `https://` 가 있는지 확인하고, 다시 요청하세요. |
| 잘못 바뀌었어요 | 세션에 "방금 변경을 되돌려 줘"라고 요청하세요. |
| 홈페이지가 그대로예요 | Actions 탭에서 실행 상태를 먼저 확인하고, 아직 실행 중이면 잠시 기다리세요. |

**하지 마세요**

- `index.html` 파일은 직접 고치지 마세요. 데이터 파일을 고치면 자동으로 다시 만들어집니다.
- 실수로 이 저장소를 지우지 마세요.

## 요청 방법의 기준 (세션 규칙)

세션은 [`docs/content-guide.md`](docs/content-guide.md)의 작성 규칙을 따릅니다. 핵심은 다음과 같습니다.

- 요청에 없는 내용은 추가하지 않습니다.
- 사실 정보는 지어내지 않습니다.
- 바꾸는 범위는 요청한 부분으로 한정합니다.
- 소식은 **제목**으로 찾습니다. 같은 제목이 여럿이면 고치지 않고 어느 것인지 묻습니다.
- 대상이 불분명하거나 근거가 없으면 고치지 않고 질문합니다.
- 작업이 끝나면 `이전 → 이후` 형식으로 무엇을 바꿨는지 보고합니다.

## 고급: 직접 실행하기 (개발자용)

### 구성

| 파일 | 역할 |
| --- | --- |
| `data/site.json` | 홈페이지 내용(제목, 소개, 소식 목록)을 담는 데이터 파일 |
| `update_homepage.py` | JSON 을 읽어 `index.html` 을 생성 |
| `index.html` | 생성된 홈페이지 (직접 수정하지 마세요) |
| `.github/workflows/update-homepage.yml` | 매일 09:00 KST 에 테스트 → 생성 → 커밋 |
| `tests/test_update_homepage.py` | 생성기 단위 테스트 |

### 데이터 형식

```json
{
  "title": "나의 홈페이지",
  "subtitle": "짧은 소개 문구",
  "lang": "ko",
  "items": [
    {
      "title": "소식 제목",
      "date": "2026-10-21",
      "summary": "요약 (선택)",
      "url": "https://example.com (선택)"
    }
  ]
}
```

- `title` 은 필수이며, 각 `items` 항목에도 `title` 이 필요합니다.
- `items` 는 `date` 기준 최신순으로 자동 정렬됩니다.
- 입력값은 HTML 이스케이프 처리되어 안전하게 출력됩니다.

### 로컬에서 생성과 테스트

```bash
python update_homepage.py
python -m unittest discover -s tests
```

### 자동 실행 설정

- **매일 자동 실행**: `.github/workflows/update-homepage.yml` 의 `cron` 값으로 주기를 바꿀 수 있습니다 (UTC 기준).
- **즉시 실행**: Actions 탭에서 `Update homepage` 를 `Run workflow` 로 실행합니다.
- **데이터 변경 시**: `data/site.json` 이나 `update_homepage.py` 를 push 하면 자동으로 다시 생성됩니다.

변경 사항이 없으면 커밋하지 않습니다.

## GitHub Pages 로 공개하기

저장소 Settings → Pages 에서 `Deploy from a branch` 를 선택하고 기본 브랜치의 `/ (root)` 를 지정하면
`https://<사용자명>.github.io/<저장소명>/` 주소로 홈페이지가 공개됩니다.

## 회원명부·방문기록·연혁 문서 자동 생성 (개발자용)

CSV 데이터를 읽어 회원명부(엑셀), 방문기록과 연혁(워드) 문서를 만듭니다. AI는 쓰지 않고 정해진 형식대로 정리합니다.

```bash
pip install -r requirements-records.txt
python generate_records.py                       # private/ 에서 읽어 out/ 에 저장
python generate_records.py --data-dir examples   # 예시 데이터로 시험
```

### 입력 파일 (`private/` 폴더)

| 파일 | 열 | 필수 |
| --- | --- | --- |
| `members.csv` | 이름, 생년월일, 연락처, 주소, 가입일, 상태 | 이름, 가입일 |
| `visits.csv` | 날짜, 시간, 방문자, 소속, 방문목적, 담당자 | 날짜, 방문자 |
| `history.csv` | 날짜, 구분, 내용 | 날짜, 내용 |

- 날짜는 `YYYY-MM-DD` 형식이어야 하며, 실제로 존재하는 날짜여야 합니다.
- 잘못된 값은 모아서 한 번에 알려 주고, 문서를 만들지 않습니다.
- 파일이 없으면 그 문서만 건너뜁니다.

### 출력 (`out/` 폴더)

- `회원명부.xlsx`: 회원명부 시트(번호 자동 부여, 필터, 머리글 고정)와 요약 시트(인원, 상태별 집계)
- `방문기록.docx`: 방문 기록 표
- `연혁.docx`: 연도별로 묶은 연혁 목록

### 개인정보 주의

- `private/` 과 `out/` 은 `.gitignore` 에 있어서 git 에 올라가지 않습니다.
- 저장소에는 `examples/` 의 가짜 데이터만 둡니다.
- 실데이터는 로컬 PC 나 개인 저장소에 보관하고, 문서는 필요한 사람에게만 전달하세요.

## 바이브 홈페이지 빌더 (`builder/index.html`)

코드를 몰라도 화면에서 내용과 디자인을 고르면 홈페이지 데이터가 만들어지는 도구입니다. 만든 데이터를 저장소에 올리면 자동화가 홈페이지를 갱신합니다.

### 어디서 여나요?

- **저장소의 GitHub Pages 주소**: 저장소 Settings → Pages 에서 `Deploy from a branch`, 기본 브랜치, `/ (root)` 를 지정하면 `https://<사용자명>.github.io/claude-project/builder/` 에서 바로 열 수 있습니다.
- **내 PC**: 저장소를 받은 뒤 `builder/index.html` 을 브라우저로 열어도 됩니다. 설치는 필요 없습니다.

### 처음부터 끝까지 (초보자용)

1. 빌더를 열고 제목, 소개, 템플릿, 색상, 소식 목록을 채웁니다. 오른쪽 미리보기에서 바로 확인합니다.
2. 아래 **검수 결과**에 빨간 ✕ 가 없는지 확인합니다. 빨간 항목이 있으면 그 항목을 먼저 고칩니다.
3. `홈페이지 데이터(site.json) 내보내기` 를 누르면 `site.json` 파일이 내려받아집니다.
4. GitHub 에서 이 저장소를 열고 `data` 폴더의 `site.json` 을 누른 뒤, 연필 아이콘(Edit)으로 내용을 바꿉니다. 또는 `data` 폴더에서 `Add file → Upload files` 로 같은 이름의 파일을 올려 덮어씁니다.
5. 아래 `Commit changes` 버튼으로 저장합니다.
6. 저장이 끝나면 자동화가 실행되어 `index.html` 을 새로 만듭니다. Actions 탭에서 초록 ✓ 이 뜨면 완료입니다.

> 데이터 파일(`site.json`)은 빌더가 만든 것을 그대로 쓰세요. 손으로 고칠 때는 큰따옴표와 쉼표를 지켜 주세요.

### 빌더가 내보내는 내용

- 제목, 한 줄 소개, 언어, 소개 글, 연락처
- 색상(강조색, 글자색, 배경색)과 글꼴 (이 세 가지만 자동 홈페이지에 반영됩니다)
- 소식 목록: 제목, 날짜, 요약, 링크

빌더의 섹션 순서, 여백, 모서리 모양은 자동화 홈페이지에 반영되지 않습니다. 이 부분까지 맞추려면 `명세서 복사` 를 이용해 AI 에게 요청하세요.

### 다른 파일 내보내기

- `index.html 다운로드`: 빌더에서 만든 완성 페이지를 그대로 받습니다. 자동화와 무관하게 따로 쓸 때 사용합니다. 자동화를 쓰는 중에는 이 파일을 저장소에 올리지 마세요. 자동화가 `index.html` 을 다시 만들어 덮어씁니다.
- `명세(JSON) 저장` / `명세 불러오기`: 빌더의 전체 설정을 파일로 보관하고 다시 열 때 씁니다.
- `AI 요청용 상세 명세서` → `명세서 복사`: 지금 설정을 AI 에게 요청할 때 그대로 붙여 넣습니다.

### 검수 규칙

- 제목 60자, 검색용 설명 160자 권장
- 글자색과 배경색 대비 4.5:1 이상 (WCAG AA), 버튼 글자와 버튼 배경 대비 4.5:1 이상
- 모든 링크는 `https://` 로 시작해야 하며, `javascript:` 같은 주소는 막힙니다.
- 날짜는 `YYYY-MM-DD` 형식이어야 합니다.

### 명세 파일

`명세(JSON) 저장` 으로 내용을 파일로 보관하고, `명세 불러오기` 로 다시 열 수 있습니다.

- 입력 내용은 브라우저에 자동 저장되며, `초기화` 로 되돌릴 수 있습니다.
- 링크는 `http://` 또는 `https://` 로 시작하는 주소만 허용합니다.
