# Cloudflare · Supabase 연결 가이드

이 문서는 저장소에서 만든 홈페이지를 **Cloudflare** 로 배포하고, **Supabase** 로 게시판 글 저장과 관리자 로그인을 붙이는 순서를 정리한 것입니다. 두 서비스 모두 **각자 가입이 필요합니다.** 이 프로그램은 대신 가입하거나 설정을 넣어 주지 않습니다.

> 현재 상태: 편집기의 **Supabase 연결** 칸(또는 `site_tool.py supabase 주소 키`)으로 연결 정보를 넣으면, 게시판에 방문자 글 칸이 생기고 `admin.html` 에 관리자 화면이 만들어집니다. Supabase 계정과 SQL 설정은 직접 해야 합니다. 이 프로그램은 Supabase 에서 실제로 실행해 본 적이 없으므로, 처음 연결할 때 글쓰기와 승인이 되는지 꼭 확인하세요.

## 0. 먼저 알아둘 것

| 서비스 | 맡는 일 | 가입 필요 | 비용 |
| --- | --- | --- | --- |
| GitHub | 코드 보관, 편집기로 만든 파일 올리기 | 예 (이미 있음) | 무료 |
| Cloudflare Pages | 저장소를 읽어 홈페이지를 만들고 공개 | 예 | 무료 범위가 있음 (사용량은 대시보드에서 확인) |
| Supabase | 게시글 저장, 승인, 관리자 로그인 | 예 | 무료 범위가 있음 |

- 세 서비스의 메뉴 이름과 버튼 위치는 바뀔 수 있습니다. 이름이 다르면 비슷한 메뉴를 고르세요.
- **비밀번호와 키는 저장소에 적지 마세요.** 이 가이드에서 말하는 키는 대시보드에서만 복사합니다.

## 1. Cloudflare Pages 로 배포하기

GitHub Pages 대신 Cloudflare 로 공개할 수 있습니다. 둘 중 **하나만** 고르세요.

1. Cloudflare 에 가입하고 대시보드에 들어갑니다.
2. **Workers & Pages → Create → Pages → Connect to Git** 을 누릅니다.
3. GitHub 계정을 연결하고 저장소 `claude-project` 를 고릅니다.
4. 빌드 설정을 다음과 같이 적습니다.

   | 항목 | 값 |
   | --- | --- |
   | Production branch | `main` (합치기 전이면 `claude/funny-franklin-mknfpi`) |
   | Root directory | `website-template` |
   | Build command | `python scripts/validate.py && python scripts/generate.py --out dist` |
   | Build output directory | `dist` |

5. **Save and Deploy** 를 누르면 `https://프로젝트이름.pages.dev` 주소가 생깁니다.
6. 빌드가 실패하면 로그에서 `설정을 고쳐 주세요` 로 시작하는 줄을 보세요. 편집기의 **검사** 와 같은 내용입니다.

**주의**
- Cloudflare 를 쓰면 저장소의 `.github/workflows/` 에 있는 배포 파일(`website-template/.github/workflows/deploy.yml` 을 루트로 복사한 것)을 **쓰지 마세요.** 둘이 같은 주소에 번갈아 올리면 서로 덮어씁니다.
- Python 버전이 맞지 않는 경우 Cloudflare 환경 변수에 `PYTHON_VERSION` = `3.12` 를 추가하세요.
- 사용자 정의 도메인(예: `www.기관이름.or.kr`)은 Pages 프로젝트의 **Custom domains** 에서 연결합니다. 도메인 등록 기관의 DNS 설정이 필요합니다.

## 2. Supabase 프로젝트 만들기

1. Supabase 에 가입하고 **New project** 를 누릅니다.
2. 이름, 데이터베이스 비밀번호, 지역(Seoul 이 가까움)을 정합니다. **데이터베이스 비밀번호는 안전한 곳에 따로 보관하세요.**
3. 프로젝트가 준비되면 **SQL Editor** 를 엽니다.
4. 저장소의 `website-template/docs/supabase-board.sql` 내용을 붙여 넣고 **Run** 을 누릅니다.
5. **Table Editor** 에 `board_posts` 테이블이 생겼는지 확인합니다.

## 3. 관리자 계정 설정 (중요)

Supabase 의 로그인 기능은 **로그인한 모든 사람을 "authenticated" 로 봅니다.** 그래서 아무나 가입할 수 있으면 아무나 관리자가 됩니다. 반드시 다음을 하세요.

1. **Authentication → Providers → Email** 에서 **Allow new users to sign up** 을 끕니다.
2. **Authentication → Users → Add user** 에서 관리자 이메일과 비밀번호로 사용자를 직접 만듭니다.
3. 관리자 이메일 로그인은 4단계의 로그인 화면에서 씁니다.

## 4. 저장소와 Supabase 를 잇기

### 4-1. 편집기에서 연결 정보 넣기

1. 편집기 맨 위 **Supabase 연결** 칸에 프로젝트 주소(`https://프로젝트.supabase.co`)를 넣습니다.
2. 키 칸에 **anon public** 키 (또는 `sb_publishable_` 로 시작하는 키)를 넣고 **연결 정보 저장** 을 누릅니다.
3. 비밀 키(`service_role`, `sb_secret_`)는 **저장되지 않습니다.** 검사가 막아 줍니다.
4. 프로젝트를 내려받아 저장소에 올립니다. 게시판에 방문자 글 칸이 생기고, `admin.html` 에 관리자 로그인 화면이 생깁니다.

터미널을 쓴다면 `python scripts/site_tool.py supabase https://프로젝트.supabase.co 키` 로 같은 일을 합니다. 연결을 지우려면 `supabase --clear` 입니다.

### 4-2. 이전 설명 (참고)

필요한 것은 다음과 같습니다.

1. **Settings → API** 에서 두 값을 복사합니다.
   - **Project URL** (예: `https://xxxx.supabase.co`)
   - **anon public** 키

   > `service_role` 키는 절대 복사해 붙이지 마세요. 누출되면 모든 보안 규칙을 무시할 수 있습니다. 이 가이드는 `anon` 키만 씁니다.

2. 이 두 값을 저장소의 설정 파일에 넣으면 됩니다. 넣는 방식은 다음 중 하나입니다.
   - 나중에 추가할 `config/supabase.json` 파일에 `{"url": "...", "anonKey": "..."}` 로 적습니다. 이 파일은 아직 없으므로 만들어야 합니다.
3. 게시판 페이지(`board.html`)에 다음 두 일을 하는 스크립트가 필요합니다. 이것도 아직 없습니다.
   - **승인된 글 읽기**: `board_posts` 에서 `approved = true` 인 글을 가져와 목록으로 보여 줍니다.
   - **글 올리기**: 방문자가 쓴 글을 `approved = false` 로 저장합니다. 화면에는 "검토 후 올라갑니다" 라고 알려 줍니다.
4. 관리자는 Supabase 의 **Table Editor** 에서 `approved` 를 `true` 로 바꾸면 게시판에 나타납니다. 관리자 로그인 화면은 로그인 후에만 승인 버튼을 보여 주도록 만들어야 합니다.

## 5. 보안 체크리스트

- [ ] 공개 가입이 꺼져 있다 (3단계)
- [ ] `anon` 키만 공개 페이지에 있고 `service_role` 키는 어디에도 없다
- [ ] 테이블의 RLS(행 단위 보안)가 켜져 있다 (`supabase-board.sql` 에 포함)
- [ ] 방문자가 올린 글은 승인 전까지 보이지 않는다
- [ ] 글 길이에 제한이 있다 (테이블의 `check` 규칙)
- [ ] 스팸이 걱정되면 Cloudflare **Turnstile**(무료 사람 확인)을 글쓰기 화면에 붙인다
- [ ] 개인정보(주민번호, 계좌, 연락처 등)를 게시판에 쓰지 않도록 안내 문구를 넣는다
- [ ] 관리자 비밀번호는 저장소 밖(비밀번호 관리자)에 보관한다

## 6. 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| Cloudflare 빌드가 실패함 | 로그의 `설정을 고쳐 주세요` 줄을 보고 편집기에서 고칩니다. Python 버전(`PYTHON_VERSION`)을 확인합니다. |
| 배포 주소에서 옛 내용이 보임 | Cloudflare 에서 **Deployments** 의 최신 배포를 확인하고, 브라우저 새로고침(강력 새로고침)을 합니다. |
| 글을 올렸는데 안 보임 | 정상입니다. 관리자가 `approved` 를 `true` 로 바꾸기 전까지는 숨겨집니다. |
| "permission denied" 오류 | RLS 정책이 빠졌거나 `anon` 키 대신 다른 키를 쓴 경우입니다. `supabase-board.sql` 을 다시 실행합니다. |
| 로그인했는데 승인 버튼이 안 보임 | 관리자 계정이 3단계로 만들어졌는지, 로그인 상태인지 확인합니다. |

## 7. 아직 확인하지 못한 것

- 실제 Supabase 프로젝트에 연결해 글쓰기, 승인, 로그인이 되는지는 이 프로그램에서 확인하지 못했습니다. 가짜 연결 객체로 화면 동작만 확인했습니다.
- 방문자 글을 서버에서 한 번 더 개인정보 검사하는 규칙(트리거)은 아직 없습니다. 지금은 방문자 화면에서만 검사합니다.
- 스팸 방지(Turnstile)는 아직 붙이지 않았습니다.
